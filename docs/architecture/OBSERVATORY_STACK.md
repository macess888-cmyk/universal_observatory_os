# Purpose

The Observatory Stack describes the major architectural layers of the Institute.

Each layer answers a different responsibility.

Each layer composes the layers beneath it.

No layer replaces the previous layer.

# Layer Responsibilities

## Institute

Purpose

Stewardship across generations.

Defines culture.

Defines responsibility.

Defines why the Observatory exists.

---

## Constitution

Defines enduring principles.

Expected to outlive implementations.

Changes only through evidence.

---

## Architecture

Defines structural organization.

Defines boundaries.

Defines engineering responsibilities.

---

## Foundation

Defines permanent observable concepts.

Examples:

- Identity
- Registry
- Relationships
- Evidence
- Timeline
- Graph

---

## Runtime

Executes inspection.

Current Runtime Pattern:

```text
Observable

↓

Validator

↓

Inspection

↓

Report
```

---

## Explorer

Provides human-centered exploration.

Helps people:

- inspect
- navigate
- compare
- preserve uncertainty

Never replaces judgment.

---

## Research

Builds higher-order inspection.

Examples:

- Formation
- Boundary
- Topology
- Geometry

Research extends the Runtime.

Research does not modify the Foundation.

---

## Domain Observatories

Future Observatory implementations.

Examples:

Software Observatory

Governance Observatory

Biology Observatory

Education Observatory

Infrastructure Observatory

Future domains inherit the Stack.

---

# Engineering Principles

Every layer possesses one responsibility.

Composition is preferred over expansion.

Architecture emerges through observation.

Unknowns remain visible.

Evidence earns revision.

Future generations remain free to improve every layer.

# Final Observation

The Observatory Stack exists to preserve architectural clarity.

Every capability should have a natural place within the Stack.

If no clear place exists,

the architecture should be revised before implementation continues.
